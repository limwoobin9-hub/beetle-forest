# 작은 숲 계정

## 사용자 흐름

오른쪽 위 **로그인 / 가입**에서 영문·숫자·밑줄 3~20자의 아이디와 8~72자의 비밀번호로 가입한다. 아이디는 대소문자를 구분하지 않는다. 이메일 입력, 인증 메일, 외부 계정 연결을 요구하지 않는다. 가입 직후 바로 로그인한다. 이메일 기반 비밀번호 찾기는 제공하지 않는다.

계정의 현실의 숲과 상상의 숲은 각각 저장된다. 빈 계정은 세계 선택 화면의 **이 브라우저 기록 가져오기**로 기존 기록을 복사할 수 있다. 로그아웃하면 비로그인 기록으로 돌아가고, 다른 계정의 곤충이나 UI 설정을 공유하지 않는다.

## 인증과 권한

- `beetle-auth` Edge Function은 아이디를 예약된 내부 Auth 식별자로 변환한다. 실제 이메일을 수집하거나 발송하지 않는다. Supabase Auth가 비밀번호 해시와 세션 발급·갱신을 처리한다.
- 가입 시 서버에서 `email_confirm: true`를 사용하므로 프로젝트 전체의 이메일 인증 설정을 바꾸지 않는다. 서버 전용 `app_metadata.app`으로 작은 숲 계정을 구분한다.
- 함수는 공개 로그인 엔드포인트이므로 플랫폼 JWT 검증을 사용하지 않는다. 함수 내부에서 프로젝트 API 키와 아이디·비밀번호를 검사하고 지속되는 IP·아이디별 시도 횟수 제한을 적용한다. 허용된 웹 출처만 CORS를 허용한다.
- 서버 비밀 키는 함수 환경변수 `SUPABASE_SECRET_KEYS`에서 읽고 레거시 환경변수는 호환용으로 사용한다. 브라우저에는 publishable 키만 있다.
- `beetle_world_saves`에 RLS를 적용하고 `auth.uid()` 소유자와 서버에서 설정한 앱 메타데이터를 검사한다. 다른 사용자의 읽기·쓰기와 비로그인 접근은 차단한다. 비밀번호나 인증 토큰을 게임 저장 테이블에 넣지 않는다.
- `beetle_auth_limits`와 시도 제한 RPC는 `service_role`만 접근한다. 저장 RPC는 `SECURITY INVOKER`로 RLS를 따른다.

## 저장

로컬 캐시는 계정 ID로 구분한다. 미전송 기록과 기준 revision을 보존하고 다시 접속할 때 서버와 비교한다. revision을 검사하는 저장 RPC로 오래된 기기가 최신 기록을 덮어쓰지 못하게 한다. 충돌 시 최신 계정 기록을 다시 불러오며, 해당 기기의 미전송 게임 상태를 복구용으로 남긴다.

## 배포와 검증

스키마는 `supabase/migrations`에, 함수는 `supabase/functions/beetle-auth`에 있다. 새 프로젝트로 옮길 때 마이그레이션과 함수를 배포한 뒤 `dist/account.js`의 프로젝트 URL과 publishable 키, 함수의 허용 출처를 변경한다. 브라우저 SDK는 버전을 고정하고 `npm run build`로 번들한다.

실제 서버에서 가입·중복 아이디·잘못된 비밀번호·아이디 대소문자 정규화·세션 갱신·두 세계 복원·비로그인 접근 차단·다른 계정의 읽기/쓰기 차단·시도 제한 RPC 접근 차단·revision 충돌을 검증했다. DOM 흐름에서 가입 화면·비밀번호 확인·기존 기록 가져오기·날짜 진행·로그아웃·재로그인·개체 복원을 확인했다.
